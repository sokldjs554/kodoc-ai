# 모델 선정 노트

"어떤 모델을 왜 골랐는가"를 기록한다. 공개 정보(모델 카드, 라이선스, 커뮤니티
벤치마크) 기반의 1차 스크리닝이며, **최종 채택은 자체 평가셋 실측을 전제로 한다** —
공개 벤치마크 순위와 특정 도메인·한국어 태스크 성능은 자주 어긋나기 때문이다.
(작성 시점 기준 정보. 모델 생태계는 빠르게 바뀌므로 주기적 재평가 대상)

## 선정 기준

1. **한국어 품질** — 사전학습 데이터에 한국어가 실질 비중으로 포함됐는가
2. **라이선스** — 상용 서비스 적용 가능 여부 (포트폴리오지만 실무 기준으로 판단)
3. **서빙 생태계** — vLLM 지원, AWQ/GPTQ 양자화 체크포인트 존재 여부
4. **크기 대비 품질** — 단일 24GB GPU에서 서빙 가능한 체급 우선

## LLM (답변 생성)

| 후보 | 판단 |
|---|---|
| **Qwen2.5-7B-Instruct (채택)** | 동급에서 한국어 품질 준수, Apache-2.0, vLLM 1급 지원, 공식 AWQ 체크포인트 제공 — 4개 기준 모두 충족 |
| EXAONE-3.5-7.8B | 한국어 특화로 유력한 대안. 라이선스가 연구용 중심이라 상용 기준에서 보류. 자체 평가셋 비교 대상 1순위 |
| Llama-3.1-8B | 생태계 최강이지만 동급 대비 한국어 출력 품질이 아쉬움 |
| SOLAR-10.7B | 한국어 강점이 있으나 세대가 앞 세대, 양자화·서빙 조합 검증 비용 고려 |

| 후보 | 판단 |
|---|---|

## 임베딩 (dense 검색)

| 후보 | 판단 |
|---|---|
| **BAAI/bge-m3 (채택)** | 다국어(한국어 포함) 검색 벤치마크 검증, dense/sparse/colbert 겸용, 8K 컨텍스트 |
| multilingual-e5-large | 견고한 대안. bge-m3 대비 차별점 부족 |
| KoSimCSE 계열 | 한국어 특화지만 관리 활발도·컨텍스트 길이에서 밀림 |

## 검증 절차 (이 저장소에서 재현 가능)

1. `eval/run_eval.py`로 검색 품질(hit@k, MRR) 측정 — 임베더는 `KODOC_EMBEDDER`로 교체
2. `benchmarks/bench_serving.py`로 서빙 성능(TTFT/TPOT/처리량) 측정 — 모델/엔진은
   서버만 바꿔 동일 명령 재실행
3. 양자화 채택 시 1·2를 양자화 전후로 반복해 품질-성능 트레이드오프 확인

모델 교체가 서비스 코드 변경 없이 가능하도록(OpenAI 호환 API + 임베더 추상화)
경계를 그어 두었으므로, 신규 모델 검증은 "서버 띄우고 스크립트 두 개 실행"으로
표준화되어 있다.
